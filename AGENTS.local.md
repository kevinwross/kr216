# AGENTS.local.md

Loaded immediately after `AGENTS.md`, and never overwritten by `DevTemplate` sync. This file is the repository's own layer: everything that is true of *this* project and not of every project.

Add entries here rather than editing the managed blocks in `AGENTS.md`; an edit inside a managed block is replaced on the next `--update` and will be lost.

**Keep this file current.** When a condition named here changes — a plan leaves DRAFT, a missing directory is created, a trap stops reproducing — update or delete the entry in the same change. A stale instruction is worse than a missing one: it is believed.

**This file holds standing rules, not status.** Progress, milestone state, counts, and completion notes belong in the project's tracker, wherever it keeps one. A recorded project had its agent append milestone state here in 117 of 135 commits: the file grew by half, and the rules governing the work changed almost every commit with nothing reviewing them.

**Standing constraints.**

- D1–D34 and Q1–Q29 are settled. Changing one takes a new plan revision and, when it touches the
  ABI, an object format or an encoding, an ADR in the repository that owns that contract.
- The encoding baseline is D26's classes and D34's `F0`: a short form exists only as a
  compression of the canonical form, and a new operation claims space in the escape class.
- Compiler-side work lives in `..\krcompiler` (D32); this repository owns the ISA, emulator,
  disassembler, image loader and the integration tests. `krdbg` changes stay upstream in
  `..\krdbg`, where the kr216 adapter is the only kr216 code.

**Tracker.** `kr216-impl.md` owns the milestone checklists, gate records and the running log.
Update it in the same change as the work it describes, and take each log entry's timestamp from
`local-datetime`.

## Definition of done

The repository is a plan until M1 creates the emulator, so a change is complete when:

- [ ] Every section, file and decision the changed text cites exists, and the counts the header
      states match the tables (`D1–D34`, `Q1–Q29`).
- [ ] A changed encoding, behaviour or contract is stated in one place and linked from the
      others that need it.
- [ ] Documentation is updated for any change to behaviour, configuration or a public interface.
- [ ] A change that alters the plan carries the next revision row and its date.
- [ ] A review of the change is reported with `BLOCKS` / `FIX-BEFORE` / `ERRATA` labels and
      evidence, in the shape of `.agents/templates/review-report.md`.
- [ ] No secrets, debug output, or unrelated edits in the diff.

When M1 lands the emulator, disassembler and image loader, replace this list with the commands
that then exist: the configure/build entry point, the encoding-vector and canonical-equivalence
runs, the bit-exact FP suite, and the decoder fuzz target.
